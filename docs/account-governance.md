# 邀请注册、邮箱与账号限制

普通账号仅通过单次邀请注册。北京时间每日最多生成一份凭证，撤销不退还额度，7 天有效；凭证只存摘要。注册、兑换、会话创建和验证邮件入队在同一 SQLite 写事务内完成。首次邮箱验证满 72 小时才能邀请；旧用户保留账号，补验证后取得发言和邀请资格。

用户入口：个人中心 →「邮箱与邀请」。可发送验证邮件、查看发送状态、生成或撤销邀请、查看公开微信申诉说明。验证邮件有效 24 小时；GET 仅显示确认页，带 CSRF 的 POST 才消费凭证。重发至少间隔 60 秒，每账号和邮箱每天最多 5 次。

管理员入口：账号管理可暂停/恢复邀请、全站封禁/解封，并填写原因及期限。封禁撤销中央会话与令牌，同时排队发送各站退出通知；各站受保护请求再查询中央状态。邀请关系页仅管理员可访问。无邀请建号和旧 toggle 接口已移除；永久删除只允许停用且没有待处理退出通知的账号。新增管理员使用受控服务器命令 `python -m app.cli set-admin --user-id <ID> --enabled --reason <原因>`，不能移除最后一位有效管理员。

用户列表的“账号限制”按钮打开独立表单，明确显示目标账号。处理原因支持多行输入且不能为空白，恢复权限时不显示期限；封禁操作显示其影响说明。注册失败也计入既有注册限流，事务回滚不消耗邀请。

申诉通过管理员微信人工处理，不创建工单或身份上传接口。收集账号标识、真实姓名、学校/班级、理由和必要证据；必要时要求补充证明，可遮挡无关信息，处理后删除。配置 `APPEAL_WECHAT_ID` 后公开说明页显示联系方式。

## 发布前检查

1. 配置 `RESEND_API_KEY`、`MAIL_FROM`（Resend 已验证的发信域名）、`APPEAL_WECHAT_ID`；保持 `BACKCHANNEL_WORKER_ENABLED`。邮件队列只保存加密链接，成功或达到重试上限后清除链接。不要把密钥写入 Git。
2. 停止应用写入，备份 SQLite；用 `python -m app.cli db-upgrade` 升级 Alembic。先在副本演练，检查 integrity_check 和 foreign_key_check。还原时恢复备份及旧发布版本，不降级丢弃数据。
3. 若启用 D1 镜像，先停止交付，核实实际镜像程序及触发器；私有 `_private_*` 邮件表必须排除。同步 users 新字段和 invitations 结构，按镜像流程重建并验证基线。D1 继续承担副本，不作为在线主库。
4. 用真实测试邮箱做一次发送和确认；核验 72 小时限制、封禁撤销和各站 503 行为。本地测试不会发真实邮件，不能替代供应商连通性检查。

后台工作线程每天清理过期验证记录（过期 30 天）、注销邀请关系（180 天）和账号处罚审计（365 天）。也可手动运行 `flask --app app:create_app governance cleanup`。邀请关系注销时立即脱离已删除用户，剩余关系记录到期删除。备份需独立执行访问权限和保留期管理。

所有仓库当前在功能分支开发；提交推送时应按项目约定先汇入 developing，再由 PR 合并 main。本次代码修改不代表已经部署。
